# 安全检测方案（通用 SOP）

本方案以 config.json 配置的公司/部门名义执行，适用于网站、Web 系统、小程序上线前安全检测。每次检测按本方案执行，产出统一模板的安全检测报告。

## 1. 目的与适用范围

- **目的**：在系统上线/提审前，系统化发现并闭环安全风险，避免「带病上线」导致的数据泄露、越权、资金损失、监管处罚与品牌受损。
- **适用对象**：网站（含政务/企业门户）、Web 业务系统（含管理后台与开放 API）、微信小程序（原生、uni-app/Taro 跨端、web-view 内嵌 H5）。
- **裁剪规则**：纯展示类网站保留维度 4/5/7/8；平台托管（PaaS/微信云开发）的项目，中间件安全按责任边界判「不适用」并在报告备注；小程序的 IPv6 支持度不适用（客户端由微信网络栈承载）。
- **强制触发场景**：首次上线、涉及支付/交易变更、重大功能更新、大促活动前、发生安全事件后、年度安全审计。

## 2. 检测依据（报告引用，做到有据可依）

| 层级 | 依据 | 用途 |
|---|---|---|
| 法律法规 | 《网络安全法》《数据安全法》《个人信息保护法》《网络数据安全管理条例》 | 合规底线 |
| 强制/推荐国标 | GB/T 22239-2019《信息安全技术 网络安全等级保护基本要求》（等保 2.0，现行，全文公开可在线预览/下载：openstd.samr.gov.cn/bzgk/std/）、GB/T 28448-2019、GB/T 35273-2020（个人信息安全规范） | 定级测评、验收 |
| 国际最佳实践 | OWASP Top 10:2025（A03 软件供应链失效为今年新晋重点，平均发生率 5.72% 居各类之首）、OWASP API Security Top 10、CVSS 3.1 | 技术漏洞分级与覆盖度 |
| 平台规范 | 《微信小程序平台运营规范》《微信小程序用户隐私保护指引》 | 小程序过审与平台合规 |

## 3. 检测对象与资产梳理（检测前先做）

1. 获取系统清单：域名/IP、开放端口、接口清单（Swagger/OpenAPI）、管理后台、测试与预发布环境、对象存储桶与云区域、开源组件清单。
2. 小程序另取：AppID、类目、代码包（.wxapkg）、服务器域名白名单、web-view 业务域名、第三方 SDK 清单。
3. 确认《用户隐私保护指引》/隐私政策配置情况，记录声明的个人信息类型与用途。

## 4. 检测维度与报告控制域映射

方案按维度组织执行，报告（《系统上线安全检测和安全措施有效性验证报告》第 5 章）按控制域记录结果，对应关系如下：

| 方案维度 | 报告控制域 |
|---|---|
| 维度 1 API 接口安全 | API 接口安全、授权管理（越权部分）、输入验证（注入部分） |
| 维度 2 业务逻辑安全 | 输入验证、授权管理（结论记录引用漏洞编号） |
| 维度 3 代码与配置安全 | 中间件安全、软件供应链、密码学安全（存储加密） |
| 维度 4 数据与密码学 | 密码学安全、API 接口安全（脱敏） |
| 维度 5 域名与暴露面 | 云暴露面、中间件安全 |
| 维度 6 隐私合规 | 个人信息保护 |
| 维度 7 平台规范合规 | 报告「评估依据/范围」章节引用说明 |
| 维度 8 安全管理制度 | 安全管理 |
| 云攻击面专项 | 云暴露面 |

标记说明：**[自]** = 工具自动化；**[人]** = 必须人工；**[半]** = 工具辅助 + 人工判断。

### 维度 1 · API 接口安全（核心，漏洞最密集）
- [半] 未授权访问：去掉 Token/Cookie 后接口是否仍返回数据。
- [人] 越权访问：水平越权（改 user_id / order_id 看他人数据）、垂直越权（普通用户调管理接口）、IDOR 遍历。
- [半] 参数篡改：金额、数量、状态、role、price 等敏感参数是否服务端校验。
- [自] 注入：SQL 注入、命令注入、XSS、SSRF（搜索框、URL 参数、评论区、上传接口）。
- [自] 频率限制：登录、短信验证码、下单接口是否有速率限制与防刷。
- [自] 敏感信息泄露：响应包是否返回手机号、身份证、openid、session_key、内部路径、堆栈。
- [自] 鉴权方式：openid+session_key、JWT、签名是否正确校验，Token 是否可伪造/过期失效。

### 维度 2 · 业务逻辑安全（自动化扫不出，最易被忽略）
- [人] 支付：金额篡改、0 元购、回调验签 + 金额校验 + 订单状态校验、重复下单（幂等）。
- [人] 优惠券/权益：重复使用、无限领取、并发超发、核销后再用。
- [人] 验证码：爆破、重放、绕过、暴力撞库。
- [人] 预约/排队：时段被脚本占满、排队号可预测（票务/挂号/活动类重点）。
- [人] 数据可见性：普通用户能否查看他人订单/资料/记录。
- [人] 流程绕过：跳过步骤直调后续接口、状态机回退。

### 维度 3 · 代码与配置安全
- [自] 反编译/前端源码泄露：小程序提取 .wxapkg（KillWxapkg/unveilr）；Web 查 source map。
- [自] 硬编码：搜索 appsecret、key、token、password、数据库地址、云 AK/SK。
- [人] 前端校验可绕过：金额、权限、必填等仅前端校验的逻辑。
- [自] 调试残留：vConsole、调试模式、demo 页面、Swagger 生产暴露。
- [自] 本地存储：是否明文存 Token/手机号/个人信息。
- [自] **软件供应链（OWASP Top 10:2025 A03）**：直接依赖 + 传递依赖版本清单（SBOM）；用 SCA 工具对 CVE/NVD/OSV 持续比对；停维、不可打补丁的组件要有替换或虚拟补丁方案。
- [半] 依赖只从官方源获取、优先签名包（防 2025 年 Shai-Hulud 类 npm 蠕虫投毒）；前端组件与小程序 SDK 同口径核查。
- [半] CI/CD 变更留痕、编写与发布职责分离、构建产物签名与不可变、灰度/分批发布控制爆炸半径（SolarWinds、Bybit 事件的共同教训：信任链上任一环失守即全线失守）。

### 维度 4 · 数据与密码学
- [自] 传输：全站 HTTPS、TLS 1.2+、证书有效、HTTP 自动跳转、无混合内容。
- [自] 存储：口令加盐散列、敏感字段加密、密钥不落地。
- [自] 展示：手机号/身份证脱敏、日志脱敏。
- [人] 密钥管理：算法与协议是否规范，是否存在前端写死密钥（等于没加密）。

### 维度 5 · 域名与暴露面
- [自] 子域名枚举、端口扫描、遗留测试域名/接口、默认口令。
- [自] 开源组件已知漏洞（Dependency-Check/Snyk）。
- [自] 管理端口与控制台收敛（对应中间件安全控制域）。

### 维度 6 · 隐私合规（监管高压线）
- [人] 隐私政策与实际收集行为逐项一致（不一致会被驳回/封禁）。
- [人] 告知-同意：主动同意、不默认勾选、不同意不强制拒绝服务（必需信息除外）。
- [人] 最小必要：不超范围收集，敏感信息单独同意。
- [人] 撤回与注销：便捷撤回、注销后彻底删除（含备份）。
- [人] 第三方 SDK 如实披露；UGC 场景接入内容安全检测。

### 维度 7 · 平台规范合规（小程序）
- [人] 提审版本与发布版本一致；类目资质齐全；诱导分享核查。

### 维度 8 · 安全管理制度（访谈 + 文档查验，等保管理要求对应项）
- [人] 管理制度：安全管理制度、操作规程、应急预案齐备且版本现行有效。
- [人] 机构与人员：安全专岗与职责书面化；人员录用/离岗账号权限交接记录；安全意识培训。
- [人] 建设管理：上线前强制安全检测有制度依据；变更与发布审批留痕（与维度 3 供应链 CI/CD 核查互证）。
- [人] 运维管理：补丁更新周期、应急预案演练记录、日志审计周期（≥6 个月，与中间件日志控制项互证）、备份策略及恢复验证。

### 云攻击面专项（对应报告「云暴露面」控制域）
工具 `scripts/cloud/cloud_scanner.py`，命令与护栏见 cloud-attack-surface.md。
- [自] S3/对象存储桶枚举与公开读写（brute-s3、check-bucket、scan-bucket）。
- [自] SSRF → 云元数据凭证探测（probe-ssrf）。
- [自] K8s 未授权探测（probe-k8s）；容器逃逸条件检测（container-escape，只检测不逃逸）。
- [自] 拿到 AK/SK 后权限枚举（exploit-creds，仅读操作；写操作须确认）。
- [人] 报错泄露、非正式镜像、部署文档与代码托管平台泄露。

## 5. 六步实施流程

1. **信息收集**：定位系统与代码包，提取域名、接口、组件、资产清单；云暴露面先做桶枚举。
2. **静态逆向**：反编译/源码审计，查硬编码、隐藏接口、危险逻辑。
3. **动态抓包**：Burp Suite / Reqable / Charles 拦截流量，梳理鉴权与参数。
4. **接口与业务测试**：自动化扫描打底 + 人工越权/支付/优惠/验证码业务推演。
5. **合规核查**：隐私指引一致性、最小必要、内容安全、平台规范逐项核对；配置基线核查。
6. **报告与复测**：整理漏洞八要素、定级排序、填控制域结果记录表出报告；整改后回归验证出复测报告。

## 6. 自动化与人工分工（关键结论）

**没有单一工具能完成全部检测。** 自动化负责「已知漏洞 + 基线 + 暴露面」（约 50-60% 检查项），人工负责「业务逻辑 + 深度越权 + 合规判断 + 报告定级」（风险最高的 40-50%）。完整方案 = 自动化漏洞扫描 + 人工渗透测试 + 代码审计。详见 tool-matrix.md。
