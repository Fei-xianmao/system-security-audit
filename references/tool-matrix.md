# 自动化 vs 人工：技术手段与工具矩阵

核心判断：**自动化工具必要但不充分。** 行业共识是「漏洞扫描 + 人工渗透测试 + 代码审计」三者结合。业务逻辑漏洞自动化扫不出来，只有理解业务流程的安全专家才能识别。

## 一、可自动化完成的检测（工具驱动，覆盖已知漏洞与基线）

| 检测目标 | 代表工具 | 自动化程度 | 说明 |
|---|---|---|---|
| 通用漏洞扫描（SQLi/XSS/CSRF/SSRF） | AWVS、Nessus、OpenVAS、OWASP ZAP | 高 | 对域名/接口批量扫描，误报需人工复核 |
| 开源组件/供应链漏洞 | OWASP Dependency-Check、Snyk | 高 | Log4j、Fastjson、Struts 等已知 CVE |
| 代码静态分析（硬编码/危险函数） | Semgrep、CodeQL | 中-高 | 业务逻辑仍需人工 |
| 小程序源码提取与敏感信息搜索 | KillWxapkg、wedecode、unveilr + grep | 高（提取）/中（判断） | 反编译 .wxapkg 后自动搜 secret/token/api |
| 弱口令检测 | Hydra、自研脚本 | 高 | 管理后台、数据库、中间件 |
| 端口/子域名/资产发现 | Nmap、Sublist3r、OneForAll | 高 | 暴露面盘点 |
| **云暴露面与凭据验证** | **scripts/cloud/cloud_scanner.py（本技能内置）** | 高 | 桶枚举/公开读写/敏感文件、SSRF→IMDS、K8s 未授权、容器逃逸条件、AK/SK 权限枚举；命令见 cloud-attack-surface.md |
| 基线配置核查 | 脚本化检查 | 高 | TLS 版本、安全响应头、调试开关、域名白名单 |
| 目录与敏感路径发现 | ffuf、dirsearch、Nikto | 高 | 找后台、找 .git/.env、找遗留测试接口 |
| SQL 注入确认与利用 | sqlmap | 高 | 注入口确认后自动确认、拖库验证影响 |
| 模板化漏洞扫描 | Nuclei | 高 | YAML 模板库上万条，社区每日更新，可当漏洞情报每日对资产扫一遍 |
| 被动代理扫描 | 长亭 Xray | 高 | 流量过一遍即出洞，与 Burp 联动，适合人工测试顺手做自动检测 |
| 利用链验证 | Metasploit | 中 | 验证漏洞真实可利用性，报告中写“已验证利用”比“疑似”有力 |
| 协议级抓包分析 | Wireshark | 中 | 代理抓不到的流量（加密前握手、内网段）做兜底分析 |
| 隐私声明文本比对 | 微信开发者工具/合规工具 | 中 | 隐私指引与接口调用字段级一致性 |

> 工具清单参考博客园《2026 年安全测试工具大全，15 款主流工具一次看懂》（2026-10），结合本技能场景整理。

## 二、必须人工的检测（专家驱动，风险最高）

| 检测目标 | 为什么必须人工 | 人工方法 |
|---|---|---|
| 业务逻辑漏洞 | 工具不理解「优惠券复用」「0 元购」等业务语义 | 手工推演流程，构造越权/重放/并发请求 |
| 水平/垂直越权、IDOR | 需理解资源归属与权限模型 | 改 user_id/order_id、删鉴权参数、切换角色 |
| 支付与优惠逻辑 | 涉及金额、回调验签、订单状态规则 | 篡改金额、重放回调、并发超发、幂等测试 |
| 验证机制 | 验证码/OTP 爆破、重放、绕过需上下文判断 | 抓包重放、时序测试、逻辑绕过 |
| 隐私合规判断 | 「最小必要」「单独同意」是法律判断 | 逐条对照《个人信息保护法》与平台指引核查 |
| 攻击链组合分析 | 多个低危串联成高危，工具不会组合 | 专家从攻击者视角串连利用链 |
| 风险定级与修复建议 | 需结合业务场景判断影响 | 专家评估 + 编写报告 |
| 云信息泄露挖掘 | 报错泄露、非正式镜像、托管平台泄露需经验判断 | 见 cloud-attack-surface.md「人工辅助」 |

## 三、常用抓包与调试工具

- **抓包代理**：Burp Suite（社区版够用）、OWASP ZAP、Reqable、Charles、Fiddler；协议级兜底 Wireshark。
- **联动扫描**：Xray 挂 Burp 被动扫描，人工点一遍即出基础洞清单。
- **强制走代理**：Proxifier / ProxyCap（PC 微信流量导入 Burp）；模拟器：雷电/蓝叠 + Fiddler；真机：Charles + CA 证书（iOS 16+ 需手动装证书）。
- **证书固定绕过**：Frida 脚本、objection（仅授权范围内）。
- **反编译/逆向**：KillWxapkg、wedecode、unveilr、wxappUnpacker；微信开发者工具导入反编译源码调试。

## 四、流水线门禁（左移，供长期建议引用）

上线检测是体检，门禁是日常：Semgrep 卡代码（SAST 规则即代码，进 CI）、Snyk 卡依赖（SCA + 容器 + IaC）、ZAP/Nuclei headless 卡部署。给客户的「长效防护建议」章节优先推这三个，成本低见效快。

## 五、执行顺序建议（由外而内）

信息收集（含云暴露面枚举）→ 静态逆向（反编译）→ 动态抓包 → 自动化扫描打底 → 人工接口与业务测试 → 合规核查 → 报告与复测。
